# Автотесты API CSMS проекта «Энергия»

Автотесты создания оператора и получения оператора по UUID. Проект написан на Python с использованием pytest, requests и Pydantic.

## Структура проекта

```text
├── tests/
│   ├── __init__.py
│   └── api/
│       ├── __init__.py
│       └── csms/
│           ├── __init__.py
│           ├── db/
│           │   ├── __init__.py
│           │   ├── operator_cleanup.py    # Очистка одного оператора, используется pytest
│           │   ├── recover_test_operators.py  # Ручная массовая очистка после сбоя
│           │   └── fixtures.py             # Фикстуры PostgreSQL
│           └── operators/
│               ├── __init__.py
│               ├── data.py                  # Фикстуры данных оператора
│               ├── model_operators.py       # Модели запроса, ответа и ошибки
│               ├── post_operators_test.py   # POST /v1/operators
│               └── get_operator_by_id_test.py  # GET /v1/operators/{id}
├── ignore/
│   └── .gitkeep
├── .env.example                             # Шаблон локальной конфигурации
├── .gitignore                               # Правила исключения файлов из Git
├── conftest.py                              # Вход в CSMS и подключение фикстур
├── README.md
├── pytest.ini                               # Настройки pytest
└── requirements.txt                         # Зависимости Python
```

## Установка и настройка

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
```

1. Укажите в `.env` адрес тестового стенда.
2. Укажите логин и пароль тестовой учётной записи Keycloak в `ENERGY_CSMS_USERNAME` и `ENERGY_CSMS_PASSWORD`.
3. Проверьте, что у учётной записи есть права на создание и чтение операторов.

Фикстура автоматически выполняет вход через Keycloak и OAuth2-коллбэк один раз за прогон pytest. Cookie сессии хранится в памяти. Если Keycloak требует OTP, прогон завершается с сообщением о причине. `.env`, содержимое `ignore/`, кэши, токены и отчёты исключены из Git.

## Запуск тестов

Перед каждым запуском обязательно:

1. Подключите VPN **NetBird** для доступа к тестовому стенду и PostgreSQL.
2. Укажите в локальном `.env` актуальные параметры подключения к PostgreSQL, включая действующие `ENERGY_CSMS_DB_USER` и `ENERGY_CSMS_DB_PASSWORD`. Для POST-тестов нужна учётная запись с правами на автоматическую очистку.
3. Для создания оператора заполните тестовые реквизиты в переменных `ENERGY_CSMS_TEST_YOOMONEY_MERCHANT`, `ENERGY_CSMS_TEST_SBERBANK_MERCHANT_LOGIN` и `ENERGY_CSMS_TEST_COMPANY_INN`.

Из корня проекта запустите:

```bash
python -m pytest -m energy_csms -rs
```

- `POST /v1/operators` проверяет HTTP 200, UUID, поля запроса и служебные поля `createdBy`, `updatedBy`, `createdAt`, `updatedAt`, `deleted` и `deletedAt` в ответах POST и последующего GET для всех 12 значений `VatType` из OpenAPI. Каждый тест с данными оператора задаёт уникальное имя с префиксом `test_`. В конце прогона сессионная фикстура находит созданных операторов и очищает их связи в четырёх схемах CSMS, в том числе после падения проверок.
- Негативные сценарии POST проверяют HTTP 400 и схему ошибки при пропуске или `null` для пяти обязательных полей, неизвестном значении НДС и массиве вместо строки.
- `GET /v1/operators/{id}` проверяет HTTP 200, поля ответа и совпадение UUID. Фикстура берёт UUID первого действующего оператора из `GET /v1/operators`. Если список пуст, pytest пропускает тест с указанием причины.

В схеме создания все шесть полей обязательны.

Для проверки сбора тестов без обращения к стенду используйте `python -m pytest --collect-only`.

## PostgreSQL

Заполните в локальном `.env` переменные `ENERGY_CSMS_DB_HOST`, `ENERGY_CSMS_DB_PORT`, `ENERGY_CSMS_DB_NAME`, `ENERGY_CSMS_DB_USER` и `ENERGY_CSMS_DB_PASSWORD`. Используйте базу того же тестового стенда, где выполняется POST.

Для автоматической очистки нужны права `SELECT` и `DELETE` на таблицы плана и право создавать временные таблицы. Pytest проверяет их до POST-сценариев с фикстурой данных оператора.

### Очистка зависимостей в базе CSMS

Команда по умолчанию показывает количество строк по таблицам для одного тестового оператора:

```bash
.venv/bin/python -m tests.api.csms.db.operator_cleanup UUID 'test_Operator имя'
```

Используйте точный UUID и полное имя. После проверки списка на тестовом стенде можно повторить команду с `--apply` и учётной записью с правами удаления. Скрипт проверяет имя во всех четырёх схемах CSMS, проходит по внешним ключам и удаляет дочерние строки раньше родительских в одной транзакции. При ошибке транзакция откатывается. POST-тесты вызывают ту же очистку автоматически в конце прогона для своих операторов.

Отдельные базы, платежи и связи, существующие только в прикладном коде или JSON, требуют отдельных проверенных правил очистки.

### Повторная очистка после сбоя

После завершения всех прогонов на тестовом стенде проверьте список оставшихся операторов.

```bash
.venv/bin/python -m tests.api.csms.db.recover_test_operators
```

Команда ищет операторов с буквальным префиксом `test_` во всех четырёх схемах CSMS, включая копии без записи в `platform.operators`. Она охватывает тестовых операторов предыдущих прогонов и операторов с таким же префиксом, созданных вручную. После проверки списка выполните очистку с правами на запись:

```bash
.venv/bin/python -m tests.api.csms.db.recover_test_operators --apply
```

У каждого оператора своя транзакция. При конфликте имён или зависимостей скрипт сообщает об ошибке и продолжает со следующим оператором. Если хотя бы одна очистка завершилась ошибкой, команда возвращает ненулевой код.
